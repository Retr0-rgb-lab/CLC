## 2. 場景單位成本（Token＋基礎設施分攤）— 全部為推算

### 2.1 四核對應的成本動作

| 產品四核 | 主要成本動作 | 是否隨「多上一節已生成的課」上升 |
|---|---|---|
| 課程生成 | 前沿模型寫課綱／講稿／檢測（**一次生成**；共享後可復用） | **否**（生成完成後讀取不另燒生成 Token） |
| 課堂上課（多模態） | 文案 LLM＋TTS 語音；可含板書圖／用戶上傳圖的視覺 Token | **否**（預設庫／共享課復用語音資產）；**是**（用戶上傳即時生成、課內追問） |

### 2.3 多模態會不會把「一單」燒穿？

| 訂單類型 | 「一單」定義 | 成本上限怎麼來 | 推算結論 |
|---|---|---|---|
| **Pro 訂閱** | 月費 HK$148 → 淨收 HK$140.62 | 月積分 11,250；滿用模型成本約 **HK$40.37**（財務模型鎖定） | 滿用貢獻約 **HK$100**（推算）→ **正貢獻** |
| **Max 訂閱** | 月費 HK$268 → 淨收 HK$256.54 | 月積分 22,500；滿用約 **HK$80.73** | 滿用貢獻約 **HK$176**（推算）→ **正貢獻** |

**語音＋圖像疊加**：同一積分池計量。用戶把額度花在圖像問答或語音課上，**總燒錢被月積分天花板卡住**；改變的是池內結構，不是打開第二個無限賬戶。

### 2.4 生成用前沿模型，會不會單門課就虧？

| 項目 | 推算 |
|---|---|
| 一門課生成成本 | ≈ HK$4–25（H5，區間視章節數與重試） |
| 誰付這筆 | 消耗**生成者當下積分**；失敗全退（定價 §2.3） |
| 之後 100 人上同一門共享課 | **不再付生成 Token**；成本變儲存／頻寬（每用戶分攤遠低於 HK$0.1 量級） |
| 與 Pro 月費對照 | 單門生成即使取上沿 HK$25，仍低於 Pro 淨收 HK$140.62 的約 18% |

風險在「同一用戶反覆整門重生成」：用積分扣費＋失敗全退邊界控制；不靠把生成降級成便宜模型（與產品鎖衝突）。

### 2.5 伺服器／算力（補齊財務模型 1.2% 雲端行）

財務模型已給出固定雲端清單（Supabase／Cloudflare／Resend／Sentry 等）。本節補**與多模態相關的變動基礎設施**，全部推算：

| 項目 | 驅動因子 | 月成本量級（推算） | 控制手段 |
|---|---|---|---|
| 物件儲存（語音檔、板書圖、上傳圖） | GB 與下載次數 | 活躍用戶人均 **HK$0.05–0.50** | 轉碼壓縮；冷熱分層；共享課單份儲存 |
| CDN／頻寬 | 語音流與圖片 | 人均 **HK$0.05–0.30** | Cloudflare 免費層優先；快取已生成資產 |
| 資料庫／Auth／向量 | MAU、課進度寫入 | 併入固定雲端 **≤HK$1,200／月**（申請驗收口徑） | 刪 Clerk／Pinecone 重複（財務模型 §2.1） |
| 可觀測性／日誌 | 事件量 | 固定檔為主 | 採樣；避免全文 Prompt 永久落盤 |
| **模型 API（TTS＋LLM＋視覺）** | 積分消耗 | **變動成本主體（≈98.8%）** | 路由、額度、降級、Free 觸頂關語音新課 |

**對老師可講的結構**：我們把算力分成「**按次計費的模型 API**」和「**近似固定的雲端底座**」。多模態變貴，貴在 API 那一層；那一層用積分與檔位封頂。雲端底座用申請額裡的營運／伺服器科目覆蓋，並設每月固定成本上限指標。

## 4. 免費／付費結構：95%／5% 怎麼辯護、怎麼壓力測試

### 4.0 客戶類型／用戶結構的完整推導依據（老師關切：為何可信）

> **本節回答「95% 免費／5% 付費從哪裡來」。** 結論先講：基準結構是**規劃假設（推算）**，落在可查證的 freemium／教育類區間內，並用單位經濟打平線反證「選 5% 留有安全邊際」；**尚無 Veridex 自身實測**。下列來源 → 步驟 → 可證偽條件寫全，方便答問與書面引用。

#### 4.0.1 鎖定的結構數字（與財務模型一致；本節不改價）

| 維度 | 基準規劃（推算） | 分母口徑（必須講清） |
|---|---|---|
| **免費：付費** | **95% : 5%** | 付費 ÷ **總用戶** ≈ 5.0%；付費 ÷ 免費 ≈ 5.26%（約 **1 : 19**） |
| **付費內 Pro : Max** | **75% : 25%** | 僅在付費用戶內；對總用戶約 **Pro 3.75%／Max 1.25%** |
| **免費額度利用率** | **40%** | 相對「每日發放積分若全用完」的比例 |
| **付費用戶利用率（成本側）** | 模型按**滿額**計成本（偏保守） | 財務模型內部不對稱假設；若實測亦僅 40%，成本更低 |
| 檔位月費 | Free **0**／Pro **148**／Max **268** | 產品鎖；本節不重開價 |

| S5 | 港區／同賽道價位樣本 | Gauth 月費約 HK$18；Sayo／升學易訂閱在 HK$150 量級有對標敘事；Hyperknow Pro ≈HK$140 | [A]/[B] 混 | 說明 Pro **HK$148** 落在「本地教育訂閱／同級 AI 學習工具」帶，**偏高端於純拍題工具**→轉化預期應低於超低價工具、高於純公益工具 |
| S6 | 香港中學生基本盤 | 中學生約 **347,820**（教育局）；DSE 年考生約 **5.5–5.8 萬** | [A] | 只定**可達市場分母**；不由此反推 5% |
| S7 | 香港學生／家長付費代理指標 | 補習「總市場規模」公開口徑互相矛盾（禁止引用單一「HK$XX 億」）；可用代理：**公開試有明確期限→付費意願季節性強**（3–5 月／9–10 月強，7–8 月弱） | [A] 學期曆 + [C] 行為判斷 | 支持「轉化集中在考試季 cohort」，年化有效付費佔比會被淡季拉低→規劃用中位 5% 而非峰值 8–9% |
| S8 | 單位經濟反證（本目錄） | 40% 利用率下打平約需 **1.7%** 付費；滿用約 **4.2%** | 推算 | **選 5% 的財務理由**：高於打平線約 3 倍（基準利用率），滿用時仍略高於打平 |

#### 4.0.3 從假設到結構的逐步推導（推算鏈）

```
步驟 1　定「付費佔總用戶」的合理區間
         下沿 S1：≈2%（全球 freemium 中位）
         上沿 S2：≈9%（Duolingo 成熟產品）
         教育類意圖高於平均 App，但品牌／留存遠弱於 Duolingo
         → 區間收斂為約 3%–7%；取中位整數 **5%** 作基準規劃。

步驟 2　用單位經濟檢查 5% 是否「會養不起免費」
         免費成本敞口由每日 60 積分封頂（滿用 ≈HK$6.46／人／月）
         利用率基準取 40%（無實測；偏「多數人不會天天用滿」的 freemium 常識）
         → 打平約 1.7%（§4.2）。5% ≈ 3×打平 → 財務上可辯護為「故意留邊際」。

步驟 3　拆付費內 Pro / Max（75:25）
         理由 A：多數付費者買「夠用的主力檔」（Pro），符合三檔產品的通用形狀（S4）。
         理由 B：必須留 Max 作重度出口，否則重度用戶退回 Free 挖額度或壓低 Pro 滿意度。
         理由 C：在 75:25 下，Max 約貢獻訂閱收入的 **38%**（財務模型 §4.2）——出口有經濟意義。
         25% 取「付費中的少數重度」整數；**非**問卷實測。

步驟 4　合成總用戶結構
         Free 95.0% ＋ Pro 3.75% ＋ Max 1.25% ＝ 100%
         對外可說「約 95% 免費、約 5% 付費；付費裡約四分之三 Pro、四分之一 Max」。

步驟 5　利用率假設分開寫
         免費 40%：獲客成本估算用（避免假設人人用滿導致過度悲觀或過度樂觀）。
         付費成本按 100% 滿額計：讓「滿用仍正貢獻」成為硬命題（Pro／Max 均成立，§3.1）。

步驟 6　標明尚未進入推導的變量
         用戶增長路徑、續訂率、CAC 實測——影響規模與現金，**不**用來反推 95／5 本身。
```

#### 4.0.4 為何不用更「好看」的比例（推算紀律）

| 若改成… | 問題 |
|---|---|
| 宣稱 10%+ 付費 | 超過 Duolingo 公開量級，零用戶階段不可辯護 |
| 宣稱 ≈2% 並當基準 | 貼近打平線／滿用時可能翻車，申請敘事會變成「剛好活」 |
| 取消 Max、只留 Pro | 重度用戶無出口；收入離散度下降，簡報亦更難答「誰付 268」 |
| 用香港補習「市場規模 HK$XX 億」反推人數 | 公開數字差數十倍，財務模型已禁用 |

**基準維持 95／5 與 Pro:Max＝75:25；本節只補全推導，不改鎖定數字。**

#### 4.0.5 可證偽條件（實測後何時改結構）

| 訊號（上線後） | 判讀 | 規格動作 |
|---|---|---|
| 付費÷總用戶 **連續 8 週 ＜2%**，且免費利用率 **＞70%** | 補貼壓力＋轉化失守 | 收緊 Free 日語音供給或觸頂規則；更新基準轉化為實測值 |
| 付費÷總用戶 **穩定 ≥8%** | 基準偏保守 | 可上調規劃轉化；**先**服務與成本承載，再談提價 |
| 付費內 Max 佔比 **＜10%** | 75:25 過高 | 改權重（例如 85:15）並重算收入餅圖 |
| 付費內 Max 佔比 **＞40%** | 重度比例高於假設 | 檢查 Pro 額度是否過緊；可保留或上調 Max 權重 |
| 免費利用率穩定落在 **20–30%** | 40% 偏悲觀 | 下調免費成本假設；打平線更寬裕 |
| 付費用戶實際積分使用 **＜50% 額度** | 「滿額計成本」過嚴 | 成本側改實測利用率；貢獻毛利上修（仍標推算至帳單穩定） |

**一句話**：95／5 可信，是因為它落在 **2.18%–9%** 的外部走廊中位、又高於我們自己的 **1.7%** 打平線，並用 Max 出口解釋收入結構；它會被 **連續低轉化＋高免費滿用** 證偽，而被證偽時改的是額度與假設，先不改 0／148／268 價位。

### 4.1 95%／5% 是什麼、不是什麼

| 是 | 不是 |
|---|---|
| 財務模型的**基準規劃假設**（落在 Adapty 2.18% 與 Duolingo 9% 之間） | 已驗證的產品事實 |
| 「付費÷總用戶≈5%」的**結構示意**（M12 推算：17,000 免費＋894 付費） | 承諾委員會的保證轉化率 |
| 用來算**免費補貼能否被付費貢獻蓋住**的分母 | 「因為有 95 個免費所以一定能養 5 個付費」的口號 |

### 4.2 盈虧平衡（推算，對齊財務模型 §1.3）

加權付費貢獻（Pro:Max＝75:25）≈ **HK$119.14／付費用戶／月**（推算）。

| 免費利用率 | 每免費用戶月成本（推算） | **打平所需付費佔總用戶** | 相對基準 5% |
|---|---|---|---|
| 100% 滿用 | HK$6.46 | **≈4.2%** | 5% 仍高於打平 |
| **40%（基準）** | **HK$2.58** | **≈1.7%** | **5% ≈ 打平線的 3 倍** |
| 30% | HK$1.94 | ≈1.3% | 安全邊際更大 |

**答「會不會養不起免費用戶」**：在基準利用率下，約每 **57 個**免費用戶需要 **1 個**加權付費用戶打平補貼；我們用 5%（約 1:19）規劃，是刻意留安全邊際。若實測轉化掉到 2% 附近，要先砍免費語音節奏或收緊觸頂，而不是先加伺服器。

### 4.3 為何要留 Max（補「只講 Pro HK$148」的淺）

| | Pro | Max |
|---|---|---|
| 佔付費用戶（假設） | 75% | 25% |
| M12 收入佔比（推算，財務模型 §4.2） | ≈62% | **≈38%** |
| 角色 | 主力訂閱 | **重度出口**：避免重度用戶擠在 Pro 或退回 Free 挖額度 |

Max＝HK$268（2026-10-16 由 388 下調）後，單位經濟仍保持滿用正貢獻（§3.1）。

### 4.4 建議對外表述的「結構」而不是單一比例

向老師／委員會講時，優先講**三層結構**，比例作附帶推算：

1. **Free**：每日成本有硬頂的體驗與獲客入口。  
2. **Pro**：主收入；滿用仍正貢獻。  
3. **Max**：重度出口；少數用戶貢獻接近四成訂閱收入（推算）。  

並主動聲明：轉化率、利用率、增長路徑**三項均無實測錨點**；首月帳單用於校準；校準前不報「保證盈利額」。

### 4.5 壓力表（推算）— 避免「只有 95／5 一張牌」

假設加權貢獻 HK$119.14／付費／月固定，只變轉化與免費利用率：

| 轉化＼利用率 | 30% | 40% | 70% | 100% |
|---|---|---|---|---|
| **2%** | 可打平有餘 | 貼近／仍可 | 壓力大 | **可能整體負貢獻** |
| **5%（基準）** | 寬裕 | **基準** | 可 | 仍高於 4.2% 打平線 |
| **8%** | 寬裕 | 寬裕 | 寬裕 | 寬裕 |

**營運含義**：真風險是「轉化低＋免費滿用」同時發生。監測指標：付費佔比、免費語音課開啟率、積分利用率、每積分實際 API 成本（定價 §14）。

### 4.6 通往「不做一單虧一單」的路徑（可執行）

| 階段 | 動作 | 驗收 |
|---|---|---|
| 上線前 | 鎖 Free 觸頂關語音、鎖加油包僅付費、鎖生成／問答路由分層 | 規格與原型一致 |
| 首月 | 實測每場景 API 帳單、利用率、圖像佔比 | 更新本文件區間；**必要時調積分消耗量**（定價已授權：消耗量可調、對外月費不變） |
| M3–M6 | 看 cohort 轉化，不看單純註冊數 | 轉化＜2% 且免費滿用 → 收緊 Free 日節奏或短講解供給 |
| 分發 | 網頁 Stripe 優先於商店 15% | 保住淨收（財務模型 §6.2） |
