## 判断标准（投影场景，不是电脑屏幕）

| 文字类型 | 下限 | 说明 |
|---|---|---|
| 页面主标题 | 40px | 已合格，不动 |
| 模块/卡片标题 | 26px | 已合格，不动 |
| **正文** | **20px** | 观众要能一眼读完 |
| 页脚、出处 | 16px | 可以小，但要能辨认 |
| 英文 kicker | 15px | 装饰性 |

## 现状实测（1920×1080 视口）

主控用浏览器逐页实测了计算字号。**标题层全部合格，问题 100% 在正文层**：

```
最小字号 9px  ← .vx-src 出处徽标
页脚    10.5px  ← .vx-foot，全篇 20 页通杀
页眉    11.5px  ← .vx-chrome
kicker  10.5px  ← .vx-cat
正文    11–17px ← 大量，分布在 18 页
```

**关键发现**：`.vx-foot`（10.5px）、`.vx-src`（9px）、`.vx-cat`（10.5px）、`.vx-chrome`（11.5px）都是**全局类**，改一次影响 10–20 页。优先改这四个，效率最高。

## 硬性约束

### 溢出处理顺序

放大后若某页溢出，**按这个顺序处理，不要先缩字号**：

1. 压缩该页的 `padding` / `margin-top`（vh 单位，每处可减 1vh）
2. 删减该页描述性文字（**只删修饰语，不删数字和结论**）
3. 仍溢出 → 该页单独降低一个档位，并在报告里说明

### 高风险页（改动后必须重点看）

| 页 | 风险原因 |
|---|---|
| **p2** | `.sigma-grid` 有 `padding-bottom:10.4vh`，`.sigma-notes p` 放大后极易顶破 |
| **p6b** | 4 个 `.shot-step`（不是 3 个），`.cite` 是完整 Cepeda 引文 |
| **p7** | 五栏布局，`.loop-box .nd` 每栏都窄 |
| **p14** | `.vx-act-d` 有 `min-height:8.4vh` 硬预留，放大后必须同步改这个值 |
| **prisk** | 四栏 × 三段文本，全篇最挤 |
| **p15b / closing** | 文字量大 |

### 禁止

- ❌ 不改页面主标题、条形图数值、大数字（`vx-num`、`vx-ratio-n`、`vx-mix-v`、HK$440,000 等）
- ❌ 不改页数（保持 20 页）
- ❌ 不改任何文字内容
- ❌ 不改 `minutes` 时长
- ❌ 不碰 CSS 的颜色、间距、布局逻辑，只改 `font-size`
- ❌ 不做繁简转换（基线已是简体）
