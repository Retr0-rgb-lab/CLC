## 0. 設計原則

1. **積分綁 token，但換算率不固定、不對外定義。** 積分是一個穩定的對外單位，背後掛的是 token；一個積分吃多少 token、token 單價多少，取決於我們路由到哪個大模型廠商的 API。
2. **積分價格與模型成本解耦——這是我們的毛利控制手段。** 同一個積分消耗量，我們可以按難度路由到不同價位的模型：**簡單的問題消耗同樣的積分，背後調用更便宜的模型，成本壓得更低，而用戶付的數不變。**
3. **只有「回看已生成的內容」免費，其餘產生生成的行為都扣積分。** 一切對話行為（課內追問、上傳時跟 Agent 對話）、課後練習與檢測、單元測驗、間隔重複回訪（若含測驗）都消耗積分。
4. **失敗全退。** 生成失敗或使用者取消，全額退回。
5. **每日發放 + 7 天結轉。** 不設窗口，不跨週期清零。
6. **觸頂不阻斷。** 額度耗盡時降級到輕量模型繼續，不設硬牆。
7. **追溯要有閘門。** 透過「深度換計價單位」控制，不是設深度上限。

> ⚠️ **2026-10-05 裁定，這條推翻了三個舊設定**，詳見 §15 決策記錄第 13–15 條：
> - ❌ 舊原則 1「積分綁語音合成量，1 積分 = 40 字」——**不再成立**。
> - ❌ 舊原則 2「只在創造新東西時扣積分」——**只剩回看免費**，其餘全扣。
> - ❌ 由此，§2 積分表的「積分」欄是**我們的定價**，不是成本換算式。**不可再用「成本」反推積分。**

### 積分消耗規則

積分是 Hyperknow 的通用額度。**只有讓 AI 為你生成新內容時才會消耗，查看已有的內容不花積分。**

| 動作 | 積分 |
|---|---|
| 提問與對話（在即時協助、課程課堂、白板或 PDF 講解中，每發送一次提問） | **1** |
| 白板 / PDF 講解課堂（在即時協助中每創建一個課堂，這次提問不再另外計費） | **5** |
| 生成課程（每門課程；每添加一個文件再加 3 個積分） | **10** |
| 課程練習（首次打開某一節的練習） | **3** |
| 單元測驗（首次打開某個單元的測驗） | **5** |
| 課程項目（首次開始項目的某個階段） | **3** |

- 練習、測驗和項目**只在首次打開時扣一次**，之後再進入不再扣積分。
- 課程生成失敗或被取消時，已扣的積分**全額退回**。
- 積分按方案的週期刷新並回到上限，**沒用完的積分不會累積到下一個週期**。
- UI 文案實例：「還剩 20 個積分 · 積分將於 10月2日 15:23 刷新」

### 從 Hyperknow 規則得出的三個判斷

**① 它的計價是「成本鏡像」，而教學價值與邊際成本反向。**

| 動作 | 積分 | 教學價值 | 每積分價值 |
|---|---|---|---|
| 提問與對話 | **1** | **最高**（診斷性、適應性） | **最高** |
| 課程項目 | 3 | 高 | 中 |
| 課程練習 | 3 | 中高 | 中 |
| 課堂 | 5 | 中（一次性、不可追問） | 中低 |
| 單元測驗 | 5 | 高（提取練習） | 中 |
| 生成課程 | 10 | 中 | **最低** |

**越困惑的學生問得越多，被收得越重。** Hyperknow 按推理邊際成本收費，而「問問題」恰恰是教學價值最高的動作。

**② 它的「每次提問扣 1 分」需要一條補丁，這條補丁證明了計價單位撐不住。**
「在即時協助中每創建一個課堂，這次提問不再另外計費」——一個設計良好的計量單位不需要這種例外。

**③ 真實用量顯示它的計價器控制的是「單次學習時段」，不是「一個月能學多少」。**
Pro 月容量 4,800 積分，但**沒有任何合理人類行為可以觸及 Max 的 18,000**（全部用於提問需要每天 600 次問題）。唯一會被卡住的是「一個晚上連續讀 4–5 次課堂」。

### 1.1 架構

**LLM 生成文案 → TTS 轉語音。** 不是實時語音對話模型。

這個選擇的成本含義：
- **成本事前完全可算**（文案字數在開課前已知），扣費可預告。
- ⛔ **已刪除「語音 99.1% / 文字 0.9%」這個比例。** 它與 §1.3 的實抓價矛盾：按 DeepSeek-V4.1-Flash 實抓，文字佔單節課總成本 **18%–29%**，不是 0.9%。

- **沒有會話長度上限問題**，不需要處理重連。

### 1.5 課內追問：消耗積分，成本隨路由浮動（2026-10-05 重寫）

> ⚠️ **本節整段重寫。** 舊版記的是「定價 0 積分但成本不是 0」的風險——**該定價已廢止**（見 §15 決策記錄第 15 條）。現在課內追問**消耗積分**，這條不再是定價與成本的不一致。

**仍然有效的成本底價（供理解量級，不可上片）：**

| 項目 | 數字 | 來源 |
|---|---|---|

| 音訊輸出單價 | **¥12 / 百萬 token** | 阿里雲百煉 [A] 2026-10 |
| **1 分鐘對談**（用戶說 1 分 + AI 回 1 分） | **HK$0.0146** | 計算 |
| **10 分鐘對談** | **約 HK$0.146** | 計算 |

> ⚠️ **上述只是音訊底價。** 阿里雲明文：**音訊輸出與對應的文字輸出分別計費**，真實課堂對話還要疊加文字輸入、文字輸出與上下文 token。

**現在的機制是什麼：**

1. 課內追問**按積分計**，與其他對話行為一致。
2. **積分消耗量由我們定，實際 token 成本由路由決定。** 簡單的追問走便宜模型，同樣扣同樣的積分——這就是 §0 原則 2 的毛利控制手段。
3. 因此**追問的成本不會失控**：它被壓在積分價格裡，而積分價格是我們可以調的。

**上線後必須實測的一項：**

- **重度用戶的即時互動佔比**（每節課追問幾分鐘）。這是決定「積分消耗量要不要跟著調」的唯一依據。**首月拿到真實課堂記錄前，積分消耗量不動。**

#### ⛔ 對外不能這樣講

- ❌ 「課內追問不另外收費」／「問到飽為止」——**已廢止**。追問消耗積分。
- ✅ 可以講：「追問跟其他課堂行為一樣扣積分，但我們會按難度自動分配模型——簡單的問題不會用貴的模型去答。」

### 1.6 成本結構：三個動作，只有一個隨規模增長（2026-10-03 重寫）

> ⚠️ **本節整表作廢重寫。** 舊版用「月積分 × 單價」算出每檔的月成本與淨利，**那個模型錯了**——它隱含假設「用戶上的每一節課都即時生成」。實際架構不是這樣。

#### 舊模型錯在哪

| 舊版的隱含假設 | 實際架構 |
|---|---|
| 每次上課都重新生成語音＋文字 | 預設課程**生成一次，之後復用** |
| 積分 = 成本對價 | 積分 = **產品節奏控制**，不是成本對價 |

**後果**：把一次性投入當成每次都要付的邊際成本，會把成本估高數倍。舊表的 −10.90／68.10／136.20 **全部不可引用**。

#### 正確的成本結構：三段

| # | 成本項 | 何時發生 | 是否隨用戶數增長 | 隨用量增長 |
|---|---|---|---|---|
| **A** | **預設課程庫** | 產品發布前一次性生成 | **否** | 否（復用） |
| **B** | **用戶上傳教材 → 即時生成** | 每次用戶上傳新教材 | 是 | 是 |
| **C** | **自定義提問** | 每次提問 | 是 | 是 |

**A 是唯一不隨用戶數增長的成本。** B 和 C 都是低頻動作——上傳教材是-once 行為，提問是課內互動。

#### 為什麼不做攤銷

預設課程庫的攤銷必須假設「攤幾年」或「攤幾個人」——**兩個分母都無法驗證，且都會被追問**。量級上也不需要攤：

- 一門課 ≈ 30 節 × 1,250 字 ≈ 37,500 字，單價約 HK$0.0064/字 → **約 HK$240/門**
- 即使做到 500 門，總投入約 HK$12 萬，與 M12 預估月收入（HK$17.7 萬）同一量級
- **攤不攤，不改變「收入量級大於課程投入」這個結論**

因此：**課程庫作為一次性投入單列，不進單客成本。** 這比假裝它是可攤銷成本更誠實。

#### 這張頁要講的一句話

> **我們的邊際成本不隨「上課次數」增長，只隨「生成新內容的次數」增長。**
> 而上課是用戶最高頻的動作，生成新內容是最低頻的動作。

這是結構性論證，不需要精確數字，也經得起追問。

#### 三個必須同時說的風險

1. **課程庫不是嚴格的一次性**——教材換版、syllabus 調整會要求持續重做，這是一條**持續投入線**，只是速率遠低於重建全庫。
2. **A/B/C 三者的實際比例完全無錨點 [D]**——預設課程覆蓋了多少上課需求，用戶多常上傳教材、多常提問，都要等實際課堂記錄。**不猜比例，不上片。**
3. **課內追問的 token 成本會隨模型路由浮動**（見 §1.5）——這已反映在計價裡（追問扣積分），不再是定價與成本不一致的風險。真正要盯的是**重度用戶的即時互動佔比**。

#### 禁用

- ❌ 不得再引用「免費 −10.90／Pro 68.10／Max 136.20」或由它們推導的毛利率
- ❌ 不得聲稱任何固定毛利率——三個假設（付費轉化率、額度利用率、A/B/C 比例）**全部無實測錨點**
- ✅ 可以說：成本結構是三段式，其中預設課程可復用、隨用戶數增長的是即時生成部分

### 2.1 免費積分的動作清單

## 6. 追溯閘門設計

### 6.1 問題的真實形狀

追溯有兩個組成部分，成本性質完全不同：

| 組成 | 成本性質 | 真實風險 |
|---|---|---|
| **定位**（找出真正不會的那一層） | 文字，一次性 | **低** |
| **補講**（把缺口補上） | **語音，按字數** | **高** |

**「無界」的是深度，而深度最終一定會變成「教學」——而教學已經有字數計價。**

### 6.2 核心機制：深度換計價單位

```
無界的文字深度 → 第 4 層自動建議「這個缺口用講的比分說的快，開一節 7 分鐘的補講？」
              → 被字數計價接管 → 「無上界」這個變數消失
```

**不是因為加了上限，而是因為深度的自然終點就是教學。** 對「用戶學到了多少」的影響接近零——追到第 4 層時用文字描述一個先備概念，本來就比直接聽一次講解更慢更難懂。

### 6.3 遞增定價

| 層 | 積分 | 理由 |
|---|---|---|
| 第 1 層（定位） | **2** | 招牌動作，必須人人做得起 |
| 第 2–3 層 | **6 / 層** | 仍在當前材料範圍內，價值明確 |
| 第 4 層起 | **12 / 層** | 越深越遠離當前材料，邊際收益遞減 |

**成本的二次化就是閘門**：10 層 = 98 積分，線性定價只需 50 積分。用戶會在追到 5–6 層時感覺到「這裡該停了」，但他仍然有權利繼續追。

### 6.4 配額

| | 免費 | Pro | Max |
|---|---|---|---|
| 每課程每週可追層數 | 3 | 12 | 不限 |

- **按「每課程每週」而非「每月總量」**——深追高度集中在 1–2 門課
- **每週重置**——學習是脈衝式的
- 免費檔的 3 層 = 剛好完成一次完整的「定位 → 補缺 → 驗證」閉環

**由到期回訪測驗觸發的追溯，不計入當週配額。** 這是產品運作得最好的那一刻，不該被攔截。理由：間隔回訪的頻率由記憶鞏固節奏決定，不是由額度決定。

### 6.5 深度探索模式（選配）

用戶可主動開啟，**預設關閉**：降價（2–3 層 4 分／層、4 層起 6 分／層）＋ 獨立深挖池。

> **自由度的主張是「選擇」，不是「無限」。開一個模式正是選擇。**

### 7.3 ⚠️ 加油包面額率決定 Max 的價格上限

```
Max 的合理價格 ≈ 0.65–0.75 ×（Pro 價格 + 補齊差額的加油包成本）
```

**Max = HK$388 落在合理區間。若把 Max 提到加油包面額率打平的位置，Max 存在的理由會歸零。**

## 8. 觸頂行為：分層降級，不設牆

抄 Gemini 官方做法：「If you have a subscription and reach your limit, you can continue your conversation with the lighter model」。

| 動作 | 額度耗盡時的行為 |
|---|---|
| 課外追問、文字動作 | 降級到輕量文字模型，**功能完整** |
| **語音課** | **降級到輕量語音模型** |
| 項目評分 | 降級到輕量模型，**並標明「此評分由輕量模型給出」** |
| 已完成的課程資產 | **永遠免費，不受降級影響** |

**降級不是懲罰，是狀態。** 這一條比爭每日 375 還是 750 積分更能決定留存。

**Free 檔同樣不設硬牆**（參考：Hyperknow Free 檔不設）。

### 8.1 免費與付費的觸頂規則不同（刻意）

| | 付費用戶觸頂 | 免費用戶觸頂 |
|---|---|---|
| 行動 | 降級不阻斷 | **語音課關閉**；文字檢測、回看、間隔重複全部繼續（0 積分） |
| 這是 | **留存**設計 | **轉化**設計 |

**產品永遠不鎖死使用者，但「開一節新的語音課」需要付費。** 這句話在答問時可以直接講。

**不用「額度不夠用」——那是 Hyperknow 的框架，無差異化。**

## 13. 禁用清單

| 禁用 | 原因 |
|---|---|
| **「1 積分 = 40 字語音」或任何「1 積分 = N token」的固定換算** | §0 原則 1：換算率不固定、不對外定義。說死會被追問「換了模型怎麼算」 |
| **用成本反推積分**（「成本 ÷ 單價 = 幾個積分」） | 積分是我們的定價，與成本解耦。這個反推方向已經不成立 |
| **「課內追問不另外收費」／「問到飽為止」** | §0 原則 3：追問消耗積分。2026-10-05 廢止 |
| **「我們比 Hyperknow 免費／上傳不收費／練習測驗免費」** | 那些動作現在都扣積分，且積分單位不可比，說了會被算出假差距 |
| **任何「1 節課 = N 積分」的固定換算** | 課的長度與內容差 50 倍，換算會錯 |
| 「約合 10／80／160 節課」 | 同上 |
| **把 Hyperknow 的 80 積分和我們的 11,250 並排** | 定義不同（窗口上限 vs 月總額），並排會被算出 14 倍差距 |
| **在量折扣上與 Hyperknow 比較** | 我們 −32%，它 26%。兩個架構的積分買不同的東西 |
| **「Max 賣能力不賣量」** | Max 是 Pro 的 **2.6 倍價**，只給 2 倍積分，這句話會被追問。說「**量是給夠的，不是拿來當賣點的**」，並把差異歸到能力與服務上 |
| 「比 ChatGPT Plus 便宜一半」 | 便宜不是護城河，且會被追問續訂率 |
| 任何成本／毛利數字上片 | 無帳單實測 |
| 「加油包是原價幾折」 | 全業界無公開數字可引 |
| 資料同步作為付費權益 | 沒有付費依據 |
| 記憶／畫像作為付費權益 | 業界從未硬鎖，硬鎖會很難看 |
| 「免費版 4 節課就夠用」 | 這是我們的推算，不是用戶反饋 |
